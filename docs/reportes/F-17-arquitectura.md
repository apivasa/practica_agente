- Verificado H-F16-01: `compareSameTime` es lexicográfico por clave fija (rango; id desc en rango 1; conclusion y `String(id)` en rangos 0 y 2), por tanto total, transitivo y determinista. Un no-`success` sin id entero nunca queda detrás de un `success` empatado: el empate ambiguo no puede dar `ok`. Las pruebas cubren permutaciones de 3 runs. Con cancelado y fallo empatados sin id, el cancelado va primero y la regla «anterior no cancelado falló» da `fail`: coherente.

Un run con `created_at` inválido da NaN en el comparador (orden inestable) y en `age > maxAgeHours` (NaN > x es falso: no se marca como viejo). La fuente es la API de GitHub, así que el riesgo es bajo. Para homogeneizarlo con `assessDeploy`, se propone un ítem: en `assessWorkflow`, un run completado con fecha inválida o futura → `fail`.
